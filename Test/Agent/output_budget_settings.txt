Output budget investigation — 2026-10-14

Shared configuration: compression inherits effective main max_tokens or max_completion_tokens. Legacy auxiliary budget fields ignored. Auxiliary reasoning remains independent. No compression-only 8192 default/floor, 32768 cap, or adaptive doubling.

Main-loop audit: no numeric output ceiling in DoraAgent/Utils or WebServer normalization; only positive integer normalization. Default remains 8192 (DeepSeek preset 64000), not a ceiling. Top-level customOptions can override max_tokens or select max_completion_tokens. MiMo preset explicitly supplies max_completion_tokens=8192; this is shared provider configuration, not a compression-only cap. Raising its UI maxTokens alone will not override that custom field; change the shared custom field too.

Context fitting currently reserves the entire configured output budget from contextWindow in both normal requests and compression; minimum input fallback is 512 tokens. Thus a max token value near or above a mistakenly small contextWindow can cause aggressive history trimming/compression. Configure the true model contextWindow first and leave meaningful input space. This behavior was retained, not relaxed or disguised as an output cap.

Official documentation verified today; suggested settings are engineering starting points, not measured optima or provider guarantees. Limits depend on the exact model, protocol and gateway. No automatic changes to saved user LLM configuration or generic default.

2026-10-14 subsequent user decision: use 64000 as the unified Dora recommendation/default across providers, rather than provider-specific starting values above. Shared main/compression configuration remains user-editable after the one-time v1 upgrade. Compression-specific reasoning is retained; auxiliary token fields are deleted by migration and ignored at runtime.
