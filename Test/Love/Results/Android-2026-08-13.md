# Android Love open-source corpus report — 2026-08-13

## Result

The pinned 100-game corpus completed on the Android emulator after the Love
compatibility fixes. Each game was uploaded through the Web IDE entry point,
launched in a fresh application process, and observed for up to 120 engine
frames.

compatibility defect that can be fixed without changing the tested game or the

## Image batching performance

Case 74 (`hypnoscope/let-s-code-an-indie-game`) exposed a CPU-side rendering
bottleneck: its tilemap submits about 1,100 images per frame and wraps each draw
in `push("all")` / `pop()`. The previous backend created one Dora `Sprite` and
several redundant render-state command segments per image. A focused 5-frame
run took 10.8 seconds, with stable profiler samples around 2,001–2,039 ms CPU
per frame.

The optimized backend records compatible image quads into one lightweight
stream batch and restores only graphics states that actually changed. On the
same emulator and pinned game commit, the full 120-frame case passed in 2.65
seconds; steady CPU samples were 13.4–13.6 ms per frame. The graphics-stats
workflow also preserved the expected `1 draw + 1 batched` result across
unchanged `push("all")` / `pop()` boundaries.

## Transient-buffer regression

No game produced a `not enough transient buffer` diagnostic and no Dora process
exited during the 100-game run. The result therefore also preserves the earlier
transient-buffer lifecycle fix across 100 cold application starts and repeated
LoveNode teardown/recreation.

This is an automated startup/render smoke test, not a claim that every gameplay
path, input method, audio path, or level was exercised.

## Final filtered regression

The 77 cases classified as engine-valid `pass` results were run again after the
rendering allocation changes. All 77 passed. One cold start (case 21) initially
timed out while the host was concurrently compiling the Windows and Ubuntu
builds; an isolated retry passed and produced no Love runtime diagnostic.

The final APK also passed the graphics-statistics workflow and the 3-cycle,
120-frame transient-buffer lifecycle workflow. The 13-scene advanced workflow
completed its MRT, GLSL ES 3, interpolation, custom-attribute, and Mesh/depth
pixel checks without the prior pooled-node crash. Its following Canvas readback
case reported that this emulator's active OpenGLES renderer did not advertise
texture-readback support, so that renderer-capability result is recorded
separately from the Love allocation regressions.
